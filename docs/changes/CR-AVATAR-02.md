# CR-AVATAR-02 虚拟人轻量状态动作

## 当前行为

v0.5 已经能在选择页和面试房间展示面试官风格绑定的静态虚拟人形象，但面试过程中虚拟人不会随流程变化。提问播报、用户听写、提交回答、生成报告等状态只散落在文字和按钮区域，侧栏虚拟人没有对应反馈。

## 目标行为

面试房间中的虚拟人根据现有面试流程切换轻量状态动作：提问、等待回答、倾听、思考、总结和只读。状态动作只在前端本地展示，不新增媒体上传、不依赖第三方数字人服务，也不阻断文字、语音、摄像头和报告流程。

## 新增内容

- 前端虚拟人状态动作枚举和展示文案；
- 虚拟人舞台状态徽标、状态说明和动态提示条；
- 提问、等待、倾听、思考、总结、只读等 CSS 轻量动作；
- 面试房间根据 `speaking`、`recognizing`、`sending`、`finishing`、面试状态和输入草稿自动切换虚拟人状态；
- v0.6 版本、任务和相关文档。

## 修改内容

- `frontend/src/services/virtualHuman.ts` 增加状态动作解析；
- `InterviewRoomView` 的虚拟人面板增加状态联动；
- `main.css` 增加轻量动作样式、状态条和降低动态效果兼容；
- 文档更新当前范围、系统架构和路线图。

## 保持不变

- 不改变登录、创建面试、提交回答、追问、结束和报告接口；
- 不改变 v0.5 的虚拟人资源 key 和静态资源映射；
- 不改变语音听写、问题播报、摄像头姿态检测和上报逻辑；
- 后端不接收原始音频、视频、截图或虚拟人动作数据。

## 本次不做

- 不实现真实口型同步；
- 不实现骨骼动画、Live2D、3D 模型或第三方数字人服务；
- 不实现管理员动作素材管理；
- 不新增虚拟人动作表或后端动作接口；
- 不用语音音频驱动表情或口型。

## 异常降级

- 浏览器禁用或降低动态效果：使用静态状态徽标和文案；
- 虚拟人资源加载失败：继续使用 v0.5 占位形象并保留状态文案；
- 语音或摄像头不可用：虚拟人状态仍能根据文字流程切换；
- 前端状态判断异常：回落到只读或等待状态，不阻断面试。

## 验收标准

- 面试房间虚拟人可根据播报问题显示提问状态；
- 语音听写或回答草稿存在时显示倾听状态；
- 提交回答和结束生成报告时显示思考状态；
- 面试完成后显示总结状态；
- 旧后端未返回 `virtualHuman` 时仍能显示默认虚拟人和状态；
- 前端 `npm run build` 通过；
- 后端 `mvn test` 通过。

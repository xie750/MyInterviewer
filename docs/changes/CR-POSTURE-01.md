# CR-POSTURE-01 摄像头姿态检测与结构化结果上报

## 当前行为

面试房间不提供摄像头预览或姿态检测。后端没有姿态事件表和接口，用户与管理员都无法查看本场面试中的姿态异常或摄像头不可用状态。

## 目标行为

用户可以在进行中面试房间开启摄像头本地检测。前端只根据浏览器本地画面采样结果生成结构化事件，后端只保存事件类型、严重级别、分数、说明和发生时间。摄像头不可用、权限拒绝或检测失败时，不阻断文字面试、语音听写、追问和报告生成。

## 新增内容

- `posture_event` 数据表；
- 姿态事件类型和严重级别枚举；
- 姿态事件上报和查询 DTO；
- 姿态事件 Mapper、Service、Controller；
- `POST /api/posture-events` 当前用户事件上报接口；
- `GET /api/interviews/{id}/posture-events` 当前用户事件查询接口；
- 面试详情姿态事件列表；
- 前端摄像头本地检测服务；
- 面试房间摄像头预览、检测状态、开关和事件列表；
- v0.4 版本、任务、API、数据库、权限和隐私文档。

## 修改内容

- `InterviewDetailResponse` 增加 `postureEvents`；
- `InterviewService` 构建详情时附带本场姿态事件；
- 前端 `InterviewRoomView` 增加姿态检测区；
- 前端类型和接口封装增加姿态事件模型与接口；
- 测试库 schema 增加 `posture_event`。

## 保持不变

- 文字面试、语音听写、问题播报、简历上下文和报告生成流程保持可用；
- 管理员后台的岗位、用户和面试记录能力保持不变；
- 后端仍不接收摄像头原始视频流或截图；
- 姿态检测失败不影响回答提交和面试结束。

## 本次不做

- 不接入外部视觉模型或云端识别；
- 不保存原始视频帧、截图或视频文件；
- 不做管理员姿态阈值配置；
- 不做全站姿态事件后台列表、搜索、导出；
- 不做虚拟人、数字人口型同步或素材后台。

## 异常降级

- 权限拒绝：关闭检测并提示用户继续文字/语音面试；
- 设备不存在：不上报原始画面，只可上报结构化不可用事件；
- 浏览器不支持：隐藏启动能力并提示继续面试；
- 上报失败：不阻断面试主流程；
- 页面离开、提交结束或检测关闭：停止摄像头轨道。

## 验收标准

- 未登录上报姿态事件返回 401；
- 用户可给自己的进行中面试上报姿态事件；
- 用户不能给他人面试上报或查询姿态事件；
- 面试详情响应包含本场姿态事件；
- 前端可开启/关闭摄像头检测，预览比例稳定；
- 摄像头不可用时文字和语音面试仍可继续；
- 后端测试和前端构建通过。

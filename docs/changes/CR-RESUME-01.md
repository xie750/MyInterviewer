# CR-RESUME-01 简历上传与临时解析

## 当前行为

用户只能基于岗位和面试官风格创建文字面试。AI 服务使用岗位提示词、风格提示词和历史问答生成首问、追问和报告，不支持简历上下文。

## 目标行为

用户可以在创建面试前上传简历，后端把文件临时解析为结构化摘要。创建面试时可把解析结果作为本场面试上下文，AI 首问、追问和报告会结合简历线索。用户也可以跳过简历，继续完整使用 v0.1 文字面试。

## 新增内容

- `/api/resumes/parse` 简历解析接口；
- `ResumeParsingService` 本地规则型解析服务；
- 简历解析请求/响应 DTO；
- `interview_session` 临时简历上下文字段；
- 前端简历上传、解析预览、清除和跳过交互；
- 简历上下文在面试详情、历史和后台列表中的使用标识；
- 简历解析与面试创建测试。

## 修改内容

- `CreateInterviewRequest` 增加可选简历解析结果；
- `InterviewAiService` 方法增加可选简历上下文参数；
- `LocalInterviewAiService` 在首问、追问和报告中使用简历摘要；
- `InterviewService` 在面试结束生成报告后清理临时简历上下文；
- API、数据库、隐私和 AI 面试文档补充 v0.2 行为。

## 保持不变

- 登录、JWT、双角色权限隔离保持不变；
- 岗位、风格、文字面试、多轮追问、报告和历史流程保持可用；
- 管理员后台不新增简历管理能力；
- 真实大模型接入仍作为后续技术增强。

## 本次不做

- 不保存原始简历文件；
- 不建立用户简历库；
- 不做管理员下载或查看简历；
- 不做语音、姿态、虚拟人相关能力；
- 不做批量上传、导出或复杂简历评分。

## 异常降级

- 简历未上传：继续文字面试；
- 格式不支持：提示用户并允许跳过；
- 内容为空：提示用户并允许跳过；
- 解析失败：不创建持久数据，并允许用户继续创建无简历面试；
- 面试结束：清理临时简历上下文。

## 验收标准

- `/api/resumes/parse` 未登录返回 401；
- 支持格式上传后返回结构化解析结果；
- 不支持格式、空文件或超过 10MB 文件返回明确错误；
- 携带简历解析结果创建面试成功，首问体现简历上下文；
- 不携带简历创建面试成功，v0.1 流程保持；
- 面试结束后会话临时简历上下文字段为空；
- 后端测试和前端构建通过。

# AI 面试设计

## v0.1 目标

MVP 已实现文字 AI 面试闭环：

- 根据岗位和面试官风格生成首次问题；
- 保存多轮对话历史；
- 根据用户回答和历史上下文追问；
- 结束后生成评分和总结报告。

## 当前实现

- 后端定义 `InterviewAiService` 作为统一 AI 能力接口；
- 当前默认实现为 `LocalInterviewAiService`，使用本地规则生成问题、追问和报告；
- Controller 不直接调用 AI 实现，面试流程由 `InterviewService` 编排；
- 真实大模型接入时可替换 `InterviewAiService` 实现，并保持 Controller 与前端接口不变。

## 面试官风格

初始包含：

- 严厉压力面；
- 温和引导面；
- 技术深挖面；
- HR 综合面。

每种风格配置：

- 名称；
- 描述；
- 专属提示词；
- 适用场景；
- 启停状态；
- 排序值。

## 提示词上下文

AI 服务使用以下上下文：

- 岗位名称；
- 岗位技术栈；
- 面试难度；
- 岗位提示词；
- 面试官风格提示词；
- 历史对话；
- 后续版本中的简历解析结果。

## 降级原则

- v0.1 在没有外部大模型供应商和 API Key 时使用本地规则型实现，保证可运行、可测试；
- 后续接入真实大模型时，如果供应商不可用，应返回明确错误或降级到本地实现，不能阻断已具备的文字面试流程；
- 语音不可用不影响文字面试；
- 简历不可用不影响基础面试。

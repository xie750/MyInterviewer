# AI 面试设计

## v0.3 目标

当前已实现文字 AI 面试闭环、可选简历上下文，以及浏览器本地语音辅助交互：

- 根据岗位和面试官风格生成首次问题；
- 根据简历临时解析结果生成更贴近经历的首次问题；
- 保存多轮对话历史；
- 根据用户回答、历史上下文和可用简历摘要追问；
- 结束后生成评分和总结报告；
- 面试结束后清理临时简历上下文。
- 用户可以用浏览器语音识别把口述内容转成文字回答，提交前仍可编辑；
- 用户可以手动或自动播报 AI 最新问题；语音失败时继续显示文字问题。

## 当前实现

- 后端定义 `InterviewAiService` 作为统一 AI 能力接口；
- 当前默认实现为 `LocalInterviewAiService`，使用本地规则生成问题、追问和报告；
- `ResumeParsingService` 使用本地规则提取简历摘要、技能关键词、项目经历和提醒；
- 前端 `voice.ts` 封装浏览器 Web Speech API，语音识别结果只进入文字回答框；
- Controller 不直接调用 AI 实现，面试流程由 `InterviewService` 编排；
- 真实大模型接入时可替换 `InterviewAiService` 实现，并保持 Controller 与前端接口不变。

## 面试官风格

初始包含：

- 严厉压力面；
- 温和引导面；
- 技术深挖面；
- HR 综合面。

每种风格配置：

- 名称；
- 描述；
- 专属提示词；
- 适用场景；
- 内置虚拟人展示配置；
- 启停状态；
- 排序值。

## 提示词上下文

AI 服务使用以下上下文：

- 岗位名称；
- 岗位技术栈；
- 面试难度；
- 岗位提示词；
- 面试官风格提示词；
- 历史对话；
- 当前面试可选简历解析结果。

## 简历上下文

- `/api/resumes/parse` 返回结构化解析结果；
- 创建面试时可把解析结果随请求提交；
- `LocalInterviewAiService` 在首问中提示候选人围绕简历技能和项目展开；
- 追问阶段会要求候选人说明简历技能的真实参与深度；
- 报告阶段会说明是否参考了简历摘要；
- 简历不可用时完全回退到岗位和风格上下文。

## 降级原则

- 当前在没有外部大模型供应商和 API Key 时使用本地规则型实现，保证可运行、可测试；
- 后续接入真实大模型时，如果供应商不可用，应返回明确错误或降级到本地实现，不能阻断已具备的文字面试流程；
- 语音不可用不影响文字面试；
- 当前 v0.3 不上传音频、不保存音频，也不新增后端语音接口；
- 简历不可用不影响基础面试。
